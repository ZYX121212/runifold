## 第一轮需要确定的六个决策

1. **请求语义**：同一逻辑请求跨传输重试使用什么键，输入摘要如何规范化，保留多久，过期后如何响应。
2. **同会话并发**：默认拒绝还是排队；分支如何显式创建；后台恢复和新请求谁先获得执行权。
3. **提交语义**：哪些事件是暂定，哪个事件代表原子提交，提交失败后客户端如何获知。
4. **取消语义**：退出订阅、取消生成、取消任务分别影响哪些资源；已完成外部结果如何保留。
5. **恢复兼容性**：工具/策略哪些变化会拒绝恢复，哪些可以兼容，谁有权声明迁移。
6. **运行模式**：保留 caller-polled 路径；托管模式的明确所有者、取消范围和预算；嵌入已有工作流时避免双重调度。

这些决策需要结合最小原型确定，不能只由 Builder 示例决定。所有不确定动作要有明确结果类型；不把“自动重试一下”作为默认兜底。

## 建议的第一批验收用例

| 用例 | 可复现设置 | 断言 |
| --- | --- | --- |
| 请求去重 | 提交后丢弃确认，再用相同键提交 | 逻辑请求只有一个，调用计数不增加 |
| 请求内容冲突 | 相同键，修改输入 | 在模型与工具调用前拒绝 |
| 会话双写 | 两个连接读取同一会话，屏障同步提交不同请求 | 只有获得准入的请求能执行变更工具 |
| 外部确认丢失 | 模拟服务持久化结果后断开连接 | 结果核对或 ambiguous；不以无证据重试通过测试 |
| 会话提交失败 | 工具完成后注入数据库提交失败 | 无 committed 事件，结果状态可追踪 |
| 流式重连 | 读取部分事件后断开，再查询/订阅 | 不启动新模型调用；快照与已提交内容一致 |
| 取消竞争 | 工具响应与取消由屏障控制顺序 | 保留已发生事实，不启动后续操作 |
| 版本变化 | 保存任务后替换同名工具的语义版本 | 不兼容变化明确拒绝或迁移 |
| 审批变更 | 发起审批后修改参数/资源版本 | 旧批准不能执行新动作 |
| 摘要冲突 | 摘要生成期间推进历史版本 | 不覆盖新历史、不使用未提交摘要 |

以上是完整目标矩阵，不能视作全部通过。研究阶段运行了六项既有测试；工程阶段新增的覆盖与限制见 RFC 0073 和当前工作区进展。

## 不进入第一轮的内容

通用 Team/Swarm、更多 Provider、自研沙箱、托管 GUI、通用记忆算法和 workspace 重构均不作为第一轮前置条件。已有预算、治理和评估设施优先复用。

第一轮成功应表现为：一个应用在正常调用、断线、冲突和重启后都能说明任务发生了什么，开发者不必重新设计整套恢复逻辑。
